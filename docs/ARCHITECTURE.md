# Engine Crates

Moved out of `AGENTS.md`. Each crate in `crates/` is an engine with no Tauri or SQLite dependency; edge modules in `src-tauri/src/` adapt them to the app.

- `crates/luminous-addons` — add-on theme runtime: Ed25519 bundle verification, ChaCha20 decryption, Store entitlement, key cache (DPAPI), in-memory URI scheme asset serving. No `tauri` or `rusqlite` (CI-checked); `commands/addons.rs` maps IPC and events at the edge.
- `crates/luminous-analysis` — offline audio analysis DSP: EBU R128 integrated loudness & true-peak calculation, mono downmixing, RMS waveforms, and 3-band FFT waveform extraction. No `tauri`, `rusqlite`, `reqwest`, or `tokio` (CI-checked); edge modules in `src-tauri` (`loudness.rs`, `waveform.rs`, `band_waveform.rs`) handle SQLite persistence, and their background analysis runs as readers scheduled by `background_reads.rs`.
- `crates/luminous-audio` — the playback engine: Symphonia decode, CPAL output, gapless/crossfade handover, gain chain, spectrum and bass-onset detection. No `tauri`, `rusqlite`, `reqwest`, or `tokio` (CI-checked); remote sources come in through the opener `media_source.rs` injects, and `audio.rs` maps `Song`/`PlayState`/pipeline info at the edge.
- `crates/luminous-devices` — portable players and removable drives: removable-volume detection (Win32 / udisks2), MTP devices (Windows Portable Devices; gvfs or kio-mtp on Linux), default device names, device profiles and the `.luminous-device.json` marker, safe eject. No `tauri`, `rusqlite` or `reqwest` (CI-checked); `devices/` owns the poll thread, `device_profiles` table and `devices-changed` event.
- `crates/luminous-equalizer` — biquad DSP filters (10-band graphic, up-to-20-band parametric with peak/shelf types), and Equalizer APO profile parser/importer. No `tauri`, `rusqlite`, `reqwest`, or `tokio` (CI-checked); presets and persistence stay in `eq_store.rs`.
- `crates/luminous-metadata` — local audio metadata and sidecar parsers: Lofty audio tag read/write, CUE sheet parsing, Dynamic Range meter log parsing, and playlist format import/export (M3U, M3U8, PLS, XSPF). No `tauri`, `rusqlite`, `reqwest`, or `tokio` (CI-checked); `collection/` and `tageditor.rs` adapt to the app's SQLite models.
- `crates/luminous-transcode` — converting library files for portable players: the "can't play" rule against a `DeviceProfile`, size estimates, decode/resample/encode (Opus via vendored libopus; AAC/MP3 via Media Foundation on Windows, `ffmpeg` on `PATH` elsewhere), art downscaling and the host-side transcode cache. No `tauri`, `rusqlite` or `reqwest` (CI-checked); `src-tauri` passes in the cache directory and exposes the encoder capabilities.
- `crates/luminous-remote` — remote wire-protocol clients: Subsonic, WebDAV, ListenBrainz, CritiqueBrainz, Lyrics (LRCLIB/NetEase/Lyrics.ovh), MusicBrainz OAuth, Radio Browser directory. No `tauri` or `rusqlite` (CI-checked); edge modules in `src-tauri` (`subsonic/`, `webdav/`, `scrobbler.rs`, `lyrics.rs`, `musicbrainz.rs`, `radio_directory.rs`) handle SQLite caching, token persistence, and Tauri events.

# Shared database contract

External tools (the Luminous MCP server) read and write columns of the app's SQLite database directly, so a column they rely on is documented here and changes only through a numbered migration in `db.rs`.

## `artist_profiles`

- `artist_key` — the artist name, `COLLATE NOCASE` (migration 83, #2097): one row per artist whatever the casing.
- `country` — added by migration 84 (#2095). An uppercase ISO 3166-1 alpha-2 code (`CA`, `US`, `FI`), or `NULL` when unknown; never a country name, a city or a state. The app fills it from MusicBrainz's artist `country` (falling back to an `area` that is itself a country) only while it is empty, so a value written by hand or by an external tool is never overwritten. It does so when Retrieve Artist Details runs and again whenever the artist's MusicBrainz details are loaded for the Info sidebar (migration 85, #2095): a blank `country` is filled on the profile whose `musicbrainz_artist_id` matches, with a column-scoped write that creates no row and touches no other column. An artist with no profile row, or none carrying that id, is left alone. Writers should store an uppercase two-letter code or `NULL`; the app's own writes normalise anything else to `NULL`. Searchable as `country:ca`.
- `tags` — a JSON array of strings, freeform per artist, with no shared vocabulary table: which tags are allowed (nationality, named awards) and which are not (genre, decade) is policy owned by the MCP server (luminous-mcp#106), not the app (#2096). The app does not filter or drop tags on save. When it saves a tag it rewrites other artists' tags that differ only in case to that spelling, so a writer that bypasses the app (the MCP server) can leave case variants, and must not assume tags it wrote are rewritten. The Genres page lists spellings that differ only by case, accents, spacing or punctuation ("Award-Winning" / "Award Winning") and merges them on request; readers wanting a tag list should case-fold the way `find_artist_tag_near_duplicates` does (`tag_dedupe_key` in `tags.rs`).

## `artist_context_enrichment`

Cache of MusicBrainz and Wikipedia data per MusicBrainz artist id; the app owns it, and readers should treat it as disposable. `country` (migration 85, #2095) is the alpha-2 code MusicBrainz gave the artist, `''` when it has none, and `NULL` for rows cached before the column existed (refetched once). `area_name` is the MusicBrainz area, which may be a city or a state, so it is not a country.
