# v3.1.0

Luminous 3.1 introduces pure-Rust ASIO output with direct hardware streaming on Windows, smart Local Library Radio from any song or artist, visual safeguards and consequence breakdowns for file organization, and massive performance improvements that eliminate library startup stalls and scrolling overhead.

### 🎛️ Audio Output & Pure-Rust ASIO
- **Direct hardware streaming with ASIO** ([#1724](https://github.com/esoltys/luminous/issues/1724), [#1263](https://github.com/esoltys/luminous/issues/1263)): Windows users can now stream audio directly to external DACs and dedicated audio interfaces via pure-Rust ASIO (`azo`) without native C++ bridge dependencies.
- **Audio device & backend selection** ([#1726](https://github.com/esoltys/luminous/issues/1726)): Choose between standard shared system audio and Direct Hardware (ASIO) in **Settings → System**, with output device picking and native driver control panel access for hardware buffer and sample rate configuration.
- **Hotplug detection & recovery**: Output streams recover automatically when audio devices are plugged in, unplugged, or changed at the system level.

### 📻 Local Library Radio
- **Instant Radio queues** ([#1579](https://github.com/esoltys/luminous/issues/1579)): Right-click any song or artist and choose **Start Song Radio** or **Start Artist Radio** to generate a dynamic, diverse 25-song queue.
- **Pure local intelligence**: Generates recommendations entirely from local library metadata—balancing genre, subgenres, release era, play history, and artist relationships without external cloud services or telemetry.

### 📁 Safe File Organization
- **Detailed confirmation safeguards** ([#1732](https://github.com/esoltys/luminous/issues/1732)): The Organize dialog now displays a full breakdown of exact file counts, affected folders, companion sidecars, and empty directory removals before moving anything on disk.
- **Draft template isolation**: Editing renaming templates pauses Auto-organize in the background, preventing half-finished patterns from touching files until explicitly confirmed.
- **Preserved artist-level sidecars** ([#1731](https://github.com/esoltys/luminous/issues/1731)): Companion assets (such as artist photos, logos, or discography sheets) are routed by scope so artist assets are never misplaced into album subfolders.

### ⚡ Performance & Reliability
- **Instant startup on large libraries** ([#1742](https://github.com/esoltys/luminous/issues/1742), [#1741](https://github.com/esoltys/luminous/issues/1741)): Streamlined database indexing and query paths, eliminating startup hangs and delayed playback on collections with 60,000+ tracks.
- **3.9x lower CPU during grid scrolling** ([#1648](https://github.com/esoltys/luminous/issues/1648)): Artwork thumbnail generation now scales card representations efficiently from 600px cached copies, drastically reducing CPU load when scrolling the Albums view.
- **Automatic WebView2 crash recovery** ([#1738](https://github.com/esoltys/luminous/issues/1738)): Luminous on Windows automatically detects WebView2 render process termination and restarts the interface seamlessly instead of showing an unresponsive blank screen.
- **Embedded lyrics scanner** ([#1721](https://github.com/esoltys/luminous/issues/1721), [#1719](https://github.com/esoltys/luminous/issues/1719)): Scans and extracts embedded `SYNCEDLYRICS` and `USLT` tags (including Vorbis comments) directly during library scans, avoiding unnecessary network lookups.
- **Coalesced file watcher notifications** ([#1746](https://github.com/esoltys/luminous/issues/1746)): Rapid tag updates (such as batch saves from MusicBrainz Picard) are coalesced into a single progress indicator without strikethrough glitches.
- **Broader Linux distribution support** ([#1700](https://github.com/esoltys/luminous/issues/1700)): Lowered the glibc baseline by building Linux release packages on Ubuntu 22.04 LTS, allowing the AppImage to run on Ubuntu 22.04, Debian 12, and other stable distributions.

### 🏗️ Architecture & Developer Ergonomics
- **Modular engine workspace crates (Epic [#1553](https://github.com/esoltys/luminous/issues/1553))**: Extracted the core playback engine (`crates/luminous-audio`, [#1556](https://github.com/esoltys/luminous/issues/1556)), biquad DSP equalizer (`crates/luminous-equalizer`, [#1554](https://github.com/esoltys/luminous/issues/1554)), and real-time spectrum analyzer ([#1555](https://github.com/esoltys/luminous/issues/1555)) into decoupled crates with zero Tauri or SQLite dependencies.
- **Versioned scripting contract** ([#1632](https://github.com/esoltys/luminous/issues/1632)): External integrations and automation tools interact through a versioned protocol handshake with bidirectional capability exchange.
- **Supply chain & formatting checks** ([#1241](https://github.com/esoltys/luminous/issues/1241), [#1736](https://github.com/esoltys/luminous/issues/1736)): Replaced `cargo-audit` with `cargo-deny` for licence and vulnerability enforcement, and integrated automated `cargo fmt` pre-commit hooks.
