## 2. Tag editor enhancements — more content in "Your collection" (`id: collection`)

Still in the same section, near the existing `song-tag-editor` / `album-tag-editor` image slots
(the paragraph starting *"Click the pencil icon next to Play all to open Edit Album Tags..."*).
Add a new paragraph after it:

> Artist, Album Artist, Composer, and Genre all accept multiple values — separate them with a
> semicolon (`Artist A; Artist B`) and Luminous keeps them as distinct, separately-searchable
> tags rather than one long string. Each of these fields (plus Title and Album) also has its own
> **Sort As** field, so you can file "The Beatles" under "Beatles, The" or a genre like "Gothic
> Metal" under a broader "Metal" without changing the tag itself. Luminous also reads legacy
> ID3v1 tags on older MP3s, and **Clear Artwork** removes embedded cover art from a track in one
> click.

No new image slots needed here — the existing `song-tag-editor` / `album-tag-editor` screenshots
already anchor this paragraph; a follow-up screenshot showing the multi-value/Sort As fields
populated is a nice-to-have, not required for this handover.

## 8. Correction: remove stale "Auto-Refill" content from "Playlists" (`id: playlists`)

Unrelated to 1.5, but flagged while working nearby: the current EN guide's Auto Playlist
paragraph reads *"Inside an Auto Playlist, flip on **Auto-Refill** to keep adding songs once you
reach the end, on top of its once-a-day refresh — and pick a flavor to bias which songs it
picks:"* followed by a list of flavor descriptions (All / Favourites / Familiar / Discover / Deep
Cuts).

**This feature doesn't exist in the app anymore** (there is no refill mechanism or Auto-Refill
setting — see `AGENTS.md`'s Architecture Invariants). Please remove that paragraph and the
flavor list entirely; Auto Playlists refresh once a day and that's it. Sanity-check the rest of
that Playlists section against a running build while you're in there, in case anything else has
drifted.
